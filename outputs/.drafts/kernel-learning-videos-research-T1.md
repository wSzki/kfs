## Findings — plausible finalists (not ranked; maximum four)

**Evidence-level result:** these are technical matches with material teaching limitations, not two confidently beginner-friendly recommendations. The lead should not convert “exact architecture/protocol” into “suitable teaching” or imply either has been visually watched. [1,10]


### A. Pritam Zope — *Create Your Own Operating System (OS) - Kernel*

- **Direct video:** https://www.youtube.com/watch?v=4hJDOvwbTZs — 59:54; 2018-01-16. [1]
- **Technical fit: exact-topic.** Original source is C + GNU-as bootstrap + ELF32 i386 + Multiboot1 + GRUB ISO + QEMU. In particular, `ld -m elf_i386` and `gcc -m32` establish a 32-bit kernel even though the emulator command is `qemu-system-x86_64`; do not misclassify the kernel as x86-64 from that executable name. [3–7]
- **Relevant source:** `Kernel/Simple/src/kernel_1`, not `NEW KERNEL`. The creator explicitly says the newer directory changed assembly syntax and build mechanism. [2]
- **Exact episode:** this standalone video. Begin at its start; no verified internal timestamps/chapters available. The description includes additional string/number/linked-list work, so the full hour is broader than the learner's first-visible-output goal. [1]
- **What is verified as explained:** source comments name magic/checksum, stack, entry point and sections; description establishes demonstration intent. No transcript was available, so **unresolved whether the video actually teaches unfamiliar assembly/C/linker syntax instead of typing it**. [1,3,5,6]
- **Prerequisites/host mismatch:** Linux i386 host and old distro/tool commands; script invokes host `gcc/as/ld`, not a named `i686-elf` toolchain, despite description calling GCC a cross compiler. This is not paste-and-run macOS ARM64 setup guidance. [1,2,4] **[INFERENCE]** learner needs a separately supplied host/toolchain bridge, plus comfort with C pointers/bitwise operations shown in source. [4,6]
- **Concrete confusion to flag:** source comment says “512 bytes” but reservation is `.skip 1024`; linker comment says “we need 1MB of space atleast” while the actual statement sets the location counter to 1M. These wording defects matter for a learner who cannot independently distinguish comments from semantics. [3,5]
- **Teaching confidence:** qualified candidate only; visual/narration/pacing not verified. No claim to have watched frames/audio. [1]

### B. sphaerophoria — *Learning (and inferring) about OS bootstrapping*

- **Direct video:** https://www.youtube.com/watch?v=gBykJMqDqH0 — 52:04; 2023-09-05. [10]
- **Technical fit: matching core topics, with final boot-route caveat.** Description names OSDev Bare_Bones; transcript explicitly compares header layouts to identify Multiboot1; discusses GRUB handing off in 32-bit mode, assembly stack/call, sample C VGA code, linker layout and QEMU. However, after narrating GRUB config/ISO creation, the end says “that's a bug with the grub part” and “for now we can get away without setting up grub.” With no verified on-screen command frames, do **not** certify that its successful final output came through ISO→GRUB rather than QEMU's direct loading path. This qualifies end-to-end exactness, not the verified C/MB1/linker teaching topics. [10]
- **Verified creator chapters:** `01:40` why cross compiler; `05:12` bootstrapper/Multiboot; `25:00` sample C kernel; `28:13` linker script; `34:20` trying/building it. These are description chapters, not inferred timestamps. [10]
- **Potential learner benefit [INFERENCE]:** it asks the right “why do these files exist?” questions aloud rather than presenting a finished code dump, and the chapters allow the assembly/C/linker pieces to be watched separately. [10]
- **Major beginner caveat:** presenter is learning and guesses rather than reliably resolving concepts. Examples in transcript: initially uncertain `.set`; BSS/statics investigation; asks whether GDT is interrupt table; linker/address/entry-point explanation repeatedly framed “my guess”/“I don't know.” The C portion says “nothing ... crazy” rather than teaching basic pointers/string semantics. [10]
- **Build distraction:** cross-compiler prebuilt before stream; later NixOS environment/PATH/Make issues, switches to shell script, missing xorriso, stale-output cleanup. **[INFERENCE]** likely too much unresolved tooling and conceptual noise for this particular overwhelmed beginner; stronger as a qualified companion than a main novice lesson. [10]
- **Visual limitation:** full auto captions read; no frame/audio watching. Spoken coverage does not establish legibility, diagrams, or slow pacing. [10]
